# إصلاحات الاعتمادية — ٩ نوفمبر ٢٠٢٦

هذه النسخة تعالج التسوية، إعادة إرسال الطلب، حدود المنتجات والعروض، القفل العام، مهلة الاتصال، الجوال بالأرقام العربية، وتعارض مسودات الإدارة.

## سلوك العمليات

- حساب المندوب: جميع التحصيلات في فترة الحساب ناقص جميع الاستلامات. يبدأ من علامة افتتاح صريحة (`النظام`، مبلغ صفر، `بداية الحساب`) عند وجودها، وليس من أول استلام حقيقي. لا يتم حذف أو تعديل استلامات سابقة أو إعادة كتابة أرصدة الإنتاج.
- الطلب: يرسل المتصفح مفتاح محاولة عشوائيًا ويحتفظ به بعد ضياع الرد وإعادة تحميل الصفحة. يسجّله الخادم مع الطلب والمخزون والمبالغ في دفعة واحدة؛ الإعادة ترجع نفس الطلب. استعمال المفتاح نفسه لمحتوى مختلف يُرفض. بعد فشل غامض وتغيير السلة، يطلب الموقع تأكيد متابعة المحاولة السابقة أولًا. لا يُخزّن رمز دخول المحفظة مع المحاولة في التخزين المحلي.
- التوافق: `walletRequestId` القديم مدعوم أيضًا. العملاء الذين لا يرسلون أي مفتاح لا يمكن ضمان منع تكرار عملياتهم. ضمان الإعادة يحتاج D1؛ لا تُنشأ محاولة جديدة بعد خطأ شبكة أو مهلة.
- الحدود: تُجمع كمية الصنف عبر السعر العادي والعروض والباقات قبل التحقق من حد المنتج. يتحقق المتصفح أيضًا قبل زيادة الباقة أو إضافة المنتج.
- الدخول: القفل يبقى لعنوان الاتصال الذي تجاوز المحاولات الخاطئة، بدل قفل جميع الأجهزة. لا يتغير رقم الموظف أو المالك.
- اتصالات JSON: مهلة ١٥ ثانية تشمل انتظار جسم الرد. عند غموض إرسال الطلب تبقى الهوية، وتعود أزرار الواجهة للعمل. تحافظ قائمة بيعات الكاشير المؤقتة على هوية البيعة عند المهلة.
- التحرير: تدخل الإدارة على أحدث بيانات من `/admin/catalog`. يُرسل `/save` بصمة `baseVersion`. يتحقق الخادم من محتوى GitHub وSHA معًا؛ تعارض القراءة أو الكتابة يرجع `data_conflict`، وتبقى مسودة المحرر. لا تتم إعادة كتابة تلقائية فوق نسخة أحدث. عند تكرار الحفظ الصحيح يُحدّث المتصفح بصمة نسخته.

## الاختبارات المحلية

```sh
node --test server/test/admin-access.mjs server/test/operations.mjs server/test/pos.mjs server/test/reliability.mjs
node server/test/staff-and-pos.mjs
node server/test/sim-4-months.mjs
node server/test/sim-5-months-all-roles.mjs
```

اختبار المتصفح، إذا كانت حزمة Playwright متاحة بالاسم الافتراضي:

```sh
node server/test/browser-reliability.cjs
```

أو حدّد مسار الحزمة عبر `PLAYWRIGHT_MODULE` ومسار Chromium عبر `CHROMIUM_PATH`. الاختبار ينشئ بيانات محلية مؤقتة، يشغّل Worker الحقيقي ضد SQLite محلية، ويحظر الاتصال بالخدمات الخارجية. لا ينفّذ عمليات على بيانات الإنتاج.

## النشر

1. نشر `server/worker.js` في العامل الحالي `ohod-admin` في Cloudflare. تبقى روابط D1 وKV والأسرار الحالية كما هي؛ لا يُطلب وضع مفاتيح في الموقع أو المستودع.
2. الجداول الجديدة تُضاف تلقائيًا عند التشغيل، بدون حذف الجداول أو الطلبات القديمة.
3. نشر الواجهة المطابقة إلى GitHub Pages، ثم تحديث الصفحة. عند نشر الواجهة قبل Worker تُفتح الإدارة للمتابعة مع تنبيه واضح؛ تظل تعديلات الكتالوج وتغيير استقبال الطلبات غير قابلة للحفظ حتى تحديث الخدمة. زر «إعادة التحقق» يفعّل الحفظ المحمي بعد وصول المسار الجديد؛ إذا كانت هناك مسودة غير محفوظة لا يعيد تحميلها فوقها، بل يطلب إبقاءها وفتح تبويب آخر.
4. التحقق في التشغيل الفعلي من فتح الإدارة والحفظ، ثم تنفيذ طلب تجريبي منسّق والتأكد من عدم تكراره ومطابقة تسوية المندوب. الاختبارات المحلية لا تثبت حالة نشر Cloudflare أو الأرصدة الفعلية.

توجد محاكاة GitHub Contents API مشتركة للاختبارات في `server/test/support/github.mjs`؛ فحص التعارض يشمل رفض نسخة قديمة وسباق PUT، ويشمل تحميل الكتالوجات التي لا يعيد GitHub محتواها كاملًا ضمن Contents API، باستخدام blob مربوط بنفس SHA.

## استكمال دمج الدخول الموحد وإصلاح تحميل الإدارة

استُكمل العمل من الفرع `unified-login` بعد دمجه مع إصلاحات الاعتمادية. بقيت تغييرات الدخول الموحد واستيراد الأصناف وإزالة واجهة البيع في المحل كما هي؛ إصلاح التحميل لا يتجاوز حماية الإصدار في `/save`.

- الخادم الحديث: تُحمّل البيانات ونسخة الإصدار من المسار المحمي، ويُختبر الحفظ بين محررين متزامنين.
- الخادم الذي يعيد `not_found` للمسار: تظهر لوحة الإدارة مع تنبيه توافق. يُجلب `data.json` بدون استخدام ذاكرة التخزين المؤقت، وتبقى البيانات محلية عند فشله. لا يُرسل `/save` بدون إصدار، حتى عند محاولة تشغيل الزر برمجيًا.
- تعذر الاتصال أو الرد غير الصحيح: يظهر عنوان «تعذر فتح الإدارة» وزر إعادة المحاولة، بدل إبقاء عنوان «جاري التحميل» بعد انتهاء الطلب. انتهاء الجلسة يبقى خاضعًا لمعالجة تسجيل الخروج الحالية.
- بعد تحديث الخدمة، تعيد المحاولة تحميل البيانات والإصدار ثم تتيح الحفظ. عند وجود مسودة لا تتلفها إعادة التحقق.
- توسع اختبار المتصفح ليغطي غياب المسار، غياب ملف المنتجات العام، حجب الحفظ، بقاء المسودة، إعادة الاتصال، وتفعيل الحفظ بعد التحديث.
