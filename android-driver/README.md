# تطبيق المندوب (أندرويد)

يفتح صفحة المندوب من موقع المتجر (فأي تعديل على الموقع يوصل التطبيق لحاله)، ومعه خدمة بالخلفية:

- **وضع «للتوصيل بس»** (من الإصدار ١٫١): لو فيه مجهز مفعّل في الإدارة، الطلب ما يوصل المندوب إلا بعد ما يعلّمه المجهز «جاهز». الإشعار يطلع «طلب جاهز للتوصيل»، والصفحة فيها «جاهزة / في الطريق / خلصت» بس، مرتبة الأقرب فالأقرب. بدون مجهز يرجع النظام القديم (المندوب يجهز ويوصّل).
- **الطلبات الجديدة:** كل ١٠ ثواني يسأل الخادم (`/driver/pending`)، وإذا فيه طلب جديد يطلع إشعار بصوت واهتزاز حتى والشاشة مقفلة.
- **تتبع الموقع:** إذا فيه طلب «في الطريق» يرسل موقع المندوب للخادم (`/driver/loc`) كل ٤ ثواني وهو يتحرك، والزبون يشوفه على الخريطة. أول ما يخلص آخر توصيل يوقف الـ GPS ويمسح الموقع.
- الرقم السري ينحفظ داخل التطبيق فقط. زر «إنهاء الدوام» في الإشعار يوقف الخدمة، وزر الخروج في الصفحة يمسح الرقم.

## بناء التطبيق

لا يحتاج Android Studio. على Ubuntu/Debian:

```
apt install openjdk-17-jdk-headless aapt dalvik-exchange apksigner zipalign python3-pil
./build.sh        # الناتج: out/ohod-driver.apk
cp out/ohod-driver.apk ../driver-app.apk   # النسخة اللي ينزّلها المندوب من الموقع
```

- **مفتاح التوقيع** ينولّد أول مرة في `keystore/` (وهو خارج git). **احتفظ فيه**: أي تحديث للتطبيق لازم ينوقّع بنفس المفتاح، وإلا لازم يمسح المندوب التطبيق القديم ويثبّت الجديد.
- لتغيير الأيقونات: `python3 tools/make-icons.py` ثم أعد البناء.

## الاختبار

```
ANDROID_JAR=/path/android-all-34.jar node test/run-core-test.mjs
```

يشغّل كود الجافا الحقيقي (`Api` و`Core`) ضد `server/worker.js` الحقيقي على قاعدة بيانات تجريبية (طلبات، إشعار الطلب الجديد، إرسال الموقع، رقم خاطئ، خادم قديم). ما يختبر واجهة أندرويد نفسها (الإشعارات والـ GPS)، هذي تنجرّب على جوال حقيقي.
